# YouTube Content OS

> An autonomous content operating system for 3 Hinglish YouTube channels, engineered for **retention, repeat viewers, and monetization probability** — not upload volume.

## Core Operating Rule

> Never ask "How do I generate a video?"
> Always ask "How do I hold a human brain for one more second?"

Every decision in this system passes through that filter (see `src/core/filter.py`).

## Channels

| # | Name | Category | Audience | Retention Target |
|---|------|----------|----------|------------------|
| 1 | **Human Decoder** | Psychology + Relationships + Behavior | 16–28 | 85%+ |
| 2 | **AI Money Lab** | AI + Side Hustles + Future Opportunities | 18–35 | 80%+ |
| 3 | **DramaVerse Interactive** | Interactive Emotional Stories | 15–30 | 90%+ |

Channel DNA is fully defined in `config/channels.yaml`.

## The 12-Engine Pipeline

```
1. Trend Intelligence       →  competitor_patterns.json
2. Audience Psychology      →  Pain/Fear/Desire/Curiosity/EmotionalTrigger/CommentTrigger
3. Script Engine            →  Spoken Hinglish, 0-2/2-8/8-18/18-25/25-30 structure
4. Anti-Repetition Memory   →  Embeddings, cosine sim >0.55 reject
5. Emotion Engine           →  emotion → speed/pitch/pause/breath markers
6. Voice Engine             →  Sarvam (primary) → ElevenLabs (fallback)
7. Visual Composition       →  40% stock / 30% AI / 20% overlays / 10% memes
8. Attention Reset          →  Reset every 1.8–4s, never allow stillness
9. HyperFrames              →  Parallax, kinetic, push, drift, shake, ramps, depth
10. Audio Engine            →  Voice + music + micro-SFX + transitions + ambient
11. Quality Gate            →  Score 6 axes, reject <8.5, auto-regenerate
12. Learning Engine         →  YouTube Analytics → winning patterns → next gen
```

The orchestrator (`src/orchestrator.py`) runs all 12 in sequence with retry loops.

## What this system OUTPUTS per video

A complete, render-ready **VideoPlan** JSON containing:

- final spoken script with emotion + pause + breath markers
- voice file (mp3) — generated by Sarvam/ElevenLabs
- scene list (timecoded) with visual asset URLs (Pexels) and effect specs
- HyperFrames scene spec (parallax/kinetic/push/drift/shake/ramps/depth)
- attention-reset cue list
- audio layer plan (music + micro-SFX + transitions + ambient)
- quality scorecard (6 axes)
- anti-repetition fingerprint
- title + description + tags + comment-pin suggestion
- end-of-video loop trigger

This plan is then consumed by the HyperFrames renderer to produce the final mp4.

## Non-Negotiables

**Never produce:** generic AI slop, PowerPoint videos, static scenes, long text blocks, fake psychology, fake money claims, copyright risk.

**Always produce:** content that feels human-made and emotionally engineered.

## Quick Start

```bash
# 1. Setup
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # fill in API keys

# 2. Daily loop
yt-os trend-scan                          # refresh competitor_patterns.json
yt-os music-scan                          # refresh trending open-source music styles
yt-os generate --channel human_decoder    # produce 1 video plan end-to-end
yt-os generate --channel ai_money_lab --render  # also render mp4 with FFmpeg
yt-os generate --channel dramaverse
yt-os ingest-analytics --csv path.csv     # feed back yesterday's results

# Or run the full daily batch:
yt-os batch --videos-per-channel 3
```

Run `yt-os status` any time to see retention scores, repetition health, and learning signals.

## Open-Source Render Stack

The default render path is **fully open-source** — no proprietary editor required:

| Layer | Tool | License |
|-------|------|---------|
| Cuts, mux, encode | [FFmpeg](https://ffmpeg.org/) | LGPL/GPL |
| Programmatic editing | [MoviePy](https://github.com/Zulko/moviepy) | MIT |
| Stock footage | [Pexels](https://www.pexels.com/api/) | Pexels License (free) |
| Music — primary | [Pixabay Music](https://pixabay.com/music/) | Pixabay Content (CC0-style) |
| Music — secondary | [Jamendo](https://www.jamendo.com/) | Creative Commons |
| Music — fallback | [Free Music Archive](https://freemusicarchive.org/) | CC / public domain |
| SFX | [Freesound](https://freesound.org/) | CC0 / CC-BY |

The `MusicTrendTracker` (`src/engines/music_trends.py`) refreshes a per-channel
mood + BPM profile from the popular endpoints of these sources, so the system
adapts to **current** music trends rather than baking in static styles. Running
`yt-os music-scan` rewrites `data/music_trends.json` weekly.

The HyperFrames spec (`src/engines/hyperframes_engine.py`) is still emitted on
every plan so you can drop it into HyperFrames later — but the FFmpeg-based
`RenderEngine` produces a finished mp4 with `yt-os generate --render`. The same
`VideoPlan` JSON also imports cleanly into other open-source editors:
**Shotcut**, **Kdenlive**, **OpenShot**, **Olive**, **Blender VSE**.

## API Keys Used

| Required for | Env var | Notes |
|--------------|---------|-------|
| Reasoning | `ANTHROPIC_API_KEY` or `OPENAI_API_KEY` | one of these recommended |
| Hinglish TTS | `SARVAM_API_KEY` | primary |
| Fallback TTS | `ELEVENLABS_API_KEY` | optional |
| Stock footage | `PEXELS_API_KEY` | |
| Music (open) | `PIXABAY_API_KEY`, `JAMENDO_CLIENT_ID` | both free, both optional |
| SFX (open) | `FREESOUND_API_KEY` | optional, falls back to curated set |
| Trends | `YOUTUBE_API_KEY`, `REDDIT_CLIENT_ID`/`REDDIT_CLIENT_SECRET` | |

The system **degrades gracefully** when keys are missing — it produces a complete
plan with mock voice / curated music / solid-colour scene placeholders so you
can validate logic before wiring real APIs.

## Reality Check

This system is calibrated to produce **8–15 short-form videos per day across 3 channels**, with retention >75% and viewed/swiped ratio >70% as the primary success metrics.

The equation:

> monetization_probability = retention × repeat_viewers × comment_activity × quality_iteration

Not upload count.
